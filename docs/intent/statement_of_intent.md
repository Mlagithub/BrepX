# 产品最终愿景声明 (Statement of Intent)

> 本文档由 `/interview-me` 经过与业务负责人的深度对齐后正式确立，作为本项目（SMLib Studio Next）后续所有架构设计、API 制定与功能实现的顶层意图宪章。

---

## 1. 成果定位 (Outcome)
打造专为 **AI + CAD + CAE (特别是 CFD 工业流体仿真全栈体系)** 设计的现代化、流体交互式、Agent 原生的三维几何建模工作台。

## 2. 目标用户 (User)
* **核心用户**：CFD 流体仿真工程师、CAE 工业软件全栈研发人员、流体机械设计工程师。
* **业务特点**：他们身兼“CAD 前处理几何修面”与“下游仿真物理场求解”两职，对传统大型 CAD 软件的繁琐低效与新人门槛深恶痛绝。

## 3. 核心价值与痛点破局 (Why Now)
* **消除重复繁琐劳动**：将长方体/圆柱/挖孔/平移等简单而高频的脏活累活，交由 Agent 通过自然语言或脚本一键代劳；
* **降低复杂高阶曲面门槛**：让新手也能通过 Agent 的协助，快速调用 SMLib 原生的放样过渡 (`Loft`)、螺旋扫掠 (`Sweep`)、空间旋转 (`Revolve`) 与 G2 曲率连续圆角；
* **双模态几何构建支持**：
  1. **从零全新参数化设计**：快速生成翼型、管道、阀体、散热流道；
  2. **外部复杂 STEP 装配体处理**：支持导入外部机械模型，利用原生算法一键剔除微小细节/倒角 (`remove_fillets`)、消除孔洞并自动缝合 (`remove_faces`)，提取水密内流体域；
* **Agent 双重角色**：既是听从指令的“执行代劳者”，又是联动下游仿真进行变体探索、参数优化的“寻优探索者”。

## 4. 交互形态 (UX Paradigm)
* **流体交互 (Blender-like UX)**：借鉴 Blender 视口中心主义（全屏视口、极简 HUD）、变换手柄 (Transform Gizmo: G 抓取平移 / R 旋转 / S 缩放)、轴向锁定 (X/Y/Z) 与数字精确定位、以及点/线/面/体分级拾取；
* **人机双向具身协同 (Embodied Agent)**：Agent 位于最顶层，与人类工程师共享同一个视口上下文；人类用鼠标点击的面，Agent 瞬间感知其法向与几何语义；Agent 输出的建议，直接在视口中以金色高亮反馈。

## 5. 成功交付标准 (Success Criteria)
1. **生成水密几何**：构建的流体域/固体域在数学上严格满足闭合、流形 (Manifold Solid)、拓扑有效；
2. **表面物理语义携带**：支持在视口中直接或通过指令对几何表面进行物理属性标注（如 `Inlet` 进口、`Outlet` 出口、`Wall` 壁面、`Interface` 流固交界面）；
3. **带属性工业标准导出**：导出的 STEP (AP242) 文件与网格数据中，表面物理语义作为原生属性完整持久化，下游仿真软件无需二次人工找面打标；
4. **全过程代码可复现**：每一次手动或 Agent 驱动的操作，均沉淀为规范、幂等的 Python `smlibpy` 脚本，天然适配自动化批处理与参数化扫描。

## 6. 严格边界与约束 (Constraints)
* 本系统**严格限定在 CAD 几何建模与几何表面物理语义标注层**。
* 交付物以高精度 B-Rep 几何文件 (STEP/STL/DXF) 和 Python 脚本为终点。

## 7. 显式非目标 (Out of Scope)
* **坚决不涉足**下游的计算流体网格剖分 (CFD Meshing，如生成四面体/多面体体网格)；
* **坚决不涉足**流体动力学物理场数值求解模拟 (CFD Solver 计算，如 Navier-Stokes 方程求解)；
* **坚决不涉足**神经网络代理模型 (AI Surrogate / PINN) 的训练与推理。
