# CFD CAD Workbench Concept: BrepX

> 本文档由 `/idea-refine` 基于与负责人的定向发散与压力测试收敛后正式确立，定义了产品核心理念、MVP 范畴与“坚决不做清单 (Not Doing)”。

---

## 1. Problem Statement (问题陈述)
> **How Might We** 为工业 CFD 全栈仿真工程师打造一个以“Blender 式视口手柄为主、Agent 具身协同为辅”的高性能 Web CAD 工作台，让工程师既能用直觉手感快速搭建参数化流道，又能一键清洗外部复杂 STEP，并将带有物理边界语义 (Inlet/Outlet/Wall) 的水密实体以通用 STEP AP242 零成本交付给下游仿真？

---

## 2. Recommended Direction: "Blender Hand + SMLib Precision + CFD Native" (流体手感 × 工业精度 × 仿真原生)

我们选定的核心方向是：**打造全球首个面向 CFD 前处理的“手柄主导型”参数化 CAD 工作台**。

### 为什么选择这个方向？
1. **符合工程师的真实心智 (视口手柄为主)**：
   CFD 工程师在探索流道布局时，最渴望的是像 Blender 一样自由直观地拉拽几何体、旋转轴向、框选倒角；如果纯靠打字与 AI 聊天，效率反而低下。
2. **Agent 作为超级副驾 (Agent 辅助为辅)**：
   Agent 不是抢夺方向盘的垄断者，而是坐在副驾的流体力学专家。当人类在视口中捏出大概轮廓时，Agent 负责处理繁琐参数计算、生成复杂放样/变径弯管、并自动识别剔除外部模型的小圆角/小安装孔。
3. **几何与物理语义伴生 (Patch-First)**：
   在建模过程中物理语义（Inlet/Outlet/Wall）随时与面绑定，并在“边界模式”下高饱和度彩色高亮，平时保持清爽；
4. **工业中立与无损交付 (STEP AP242)**：
   坚决不搞私有格式绑架，最终交付物为国际标准的 STEP AP242（包含 Face 拓扑命名元数据），任意导入 ANSYS Fluent、OpenFOAM、Star-CCM+、SU2 等求解器均可被下游网格剖分工具完美读取。

---

## 3. Key Assumptions to Validate (核心假设与验证策略)

- [ ] **假设 1：前端 Three.js 本地显存拖拽 + 松手触发 Python SMLib 求解能够兼顾 60 FPS 流畅度与数学精度**
  - *验证方法*：在当前已上线的 TransformControls 手柄中进行快速连续旋转/平移，实测视口无网络等待掉帧，松手后后端在 20ms 内完成 B-Rep 更新。
- [ ] **假设 2：主流 CFD 网格前处理工具 (如 Fluent Meshing, Gmsh) 能够准确读取 STEP AP242 中写入的 Face Name 属性**
  - *验证方法*：导出带有 `inlet_1`, `outlet_1` 属性的 STEP 文件，用开源 Gmsh 与 FreeCAD 打开，确认面名称属性完整保留且不乱码。
- [ ] **假设 3：SMLib 原生 `remove_fillets` 和 `remove_faces` 能够稳定处理从 SolidWorks/NX 导出的复杂外部装配体**
  - *验证方法*：收集 3 个真实的工业机械阀体/管道 STEP 模型，测试一键擦除倒角与缝合螺栓孔的成功率。

## 4. MVP Scope (第一期极简交付范畴)

### 核心必须做 (In Scope):
1. **全屏沉浸视口 + 核心快捷手柄**：
   - 键盘 `G` (移动)、`R` (旋转)、`S` (缩放)，支持拖拽中按 `X/Y/Z` 锁定单轴；
   - `Shift + A` 就地呼出浮动添加菜单；
   - `Tab` 切换对象模式与编辑模式，`1/2/3` 快速切换点线面；
   - `Alt + Z` 实时切换 X-Ray 半透明透视观察内部流道。
2. **CFD 物理边界打标工作流**：
   - 顶部提供一键切换【🌊 边界模式】：开启时入口深蓝、出口玫红、壁面冷灰、交界面暖橙；平时保持金属天蓝色；
   - 选定面一键打标；
   - 一键导出标准 STEP AP242 与配套 CFD 边界条件字典 (JSON)。
3. **双模几何构建引擎**：
   - 从零参数化生成典型流体构件（文丘里喷嘴、90°弯管、法兰管道）；
   - 一键去特征化（消除微小圆角 `remove_fillets`）与反向内流体域提取 (`cavity_extraction`)。
4. **Agent 副驾协同**：
   - 侧边保留极简聊天框，支持自然语言一键微调、自愈纠错与多轮对话。

## 5. Not Doing List (坚决不做清单 —— 保持极致克制)

* **坚决不做体网格剖分 (Meshing)**：不集成 tet/hex 体网格生成器（下游有极其专业的 snappyHexMesh, Fluent Meshing, Gmsh，在 CAD 阶段硬做只会导致软件臃肿且质量难以匹敌工业网格器）；
* **坚决不做流场物理求解 (Solver)**：不内置 Navier-Stokes 求解器计算；
* **坚决不做代理模型 (Surrogate AI) 训练管线**：不搞端到端深度学习训练黑盒，保持纯正、可靠、高精度的几何工具底座定位；
* **坚决不发明私有拓扑修改器对象树**：像 Blender 保持 Original 脚本不可变一样，以干净可读的 Python `smlibpy` 脚本作为单一真实源，从根本上消灭拓扑命名崩溃；
* **坚决不设计深层繁复的 Windows 嵌套弹窗**：所有操作尽量在视口内通过手柄、快捷键和轻量浮动面板就地完成。

## 6. Open Questions (后续工程推进需关注点)
1. **超大装配体轻量化加载**：当外部导入的 STEP 超过 100 MB 时，如何优化 SMLib 的三角化剖分速度与 WebGL 渲染管线内存占用；
2. **多流体域与多胞体管理**：对于带有固体壁厚与内部流体的流固耦合模型（FSI），如何更直观地在视口中隔离查看固体壳与内部流体腔。
